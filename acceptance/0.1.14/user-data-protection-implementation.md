## 实际修改

- `electron/reader-custom-api.cjs`：读取服务元数据时不解密；每个服务在实际使用密钥时独立解密和记录状态。写入按队列串行，保留未替换密文，先写入并同步、校验临时文件，再原子替换；失败清理临时文件。v1 首次写入 v2 前独立保留原文件；旧记录无 ID 时按非秘密元数据确定稳定 ID。
- `src/reader/custom-api-settings.tsx`：显示密钥记录的检查状态，测试连接后刷新状态。历史密文可能代表空密钥，因此未经解密时标为“存在密钥记录，尚未检查”。
- `tests/reader-custom-api.test.mjs`：使用模拟安全存储和临时目录验证多服务隔离、不可用与无效密文、保存失败、v1 原件保存和首次读取不访问 Keychain。
- `packages/reader/src/server/app.test.ts`：对已有“后台导读失败”模拟测试使用零等待重试；保留原断言。首次离线套件因每篇文章的默认重试等待超过 20 秒而失败，调整测试等待后通过。

## 阶段结果

### A. API 配置：部分完成

列表读取保留服务名、地址、模型、ID 和激活状态，不因单条密钥失败而失去列表。`missing`、`empty_key`、`unchecked`、`available`、`keychain_unavailable`、`invalid_ciphertext` 和 `credential_unavailable` 已在内部表示。由于同步 `safeStorage` 的异常不足以可靠区分授权拒绝与密文损坏，解密抛错统一报告 `credential_unavailable`，不猜测具体原因。损坏 JSON、未知版本用不同错误码拒绝覆盖。故障后可重试，或输入新密钥替换该服务密文；空输入保留原密文。

未完成：真实 macOS Keychain 互动、跨签名版本升级、所有状态的完整 Renderer→主进程交互测试。错误码尚未完整穿过全部 IPC/API，界面主要依赖安全错误文字与状态；不应把本阶段称为完全验收。旧版空密钥只有真正解密后才能确定为空，不能从密文记录推断。v1 备份是本机安全恢复材料，未验证跨设备可解密。

### B. 统一备份与恢复：未实现

没有新增完整备份入口、恢复点、恢复日志、进度、取消或崩溃回滚。现有 Reader v1 JSON 备份依旧只覆盖原有阅读白名单及适配的模型缓存和成长记录；它不包含 EPUB、API 配置、Agent 会话和 Codex 凭据。普通 JSON 可能包含私人阅读资料，且并未加密。本阶段后续新增的 Reader ZIP 备份实现见 `reader-backup-implementation.md`；其产品范围不含原始书刊和附属媒体。

具体架构缺口：Reader iframe 的 localStorage、宿主 localStorage、Reader utility process 写入的书库和 Agent Runtime 的会话文件由不同进程分别管理，现有应用没有可验证的统一停写屏障、持久化事务日志，也没有在各服务初始化前执行未完成事务恢复的入口。现有 Reader 恢复仅作内存级尽力回滚（`scripts/reader-data-management.tsx` 和 `scripts/reader-backup-adapter.mjs`）。如果直接将多处文件覆盖，会在进程退出或断电时留下混合状态。尚未实现并验证这些前置机制，因此未暴露可能损坏用户数据的完整恢复操作。

后续恢复实施：先引入 Reader 专属一致性与恢复屏障，使用隔离用户数据对每个提交点注入失败及进程终止；再加入严格清单和哈希验证、路径/符号链接/大小限制、版本化 staging 和持久恢复点；恢复时只还原阅读数据、学习数据、设置和书库索引，不还原书刊原件，缺源时保留关联并提示重新导入/关联。普通备份必须排除 API Key、密文、Cookie 和 Codex 身份凭据。

### C. 升级及迁移：未完成

除 API v1 原文件保留与现有 Beta 路径逻辑外，没有实现统一 schema 版本门禁、升级快照、旧版写入阻断、外置 userData 挂载身份验证、整机迁移保护或软件更新备份提醒。长期规则是未来发布门禁，不能代替现有功能与测试。
