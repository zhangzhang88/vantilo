## Reader session authentication

The ordinary app and preview builds require a fresh per-start session token for Reader's non-health HTTP endpoints. Electron installs it as a host-only, Secure, HttpOnly cookie before Reader is marked ready; a failed installation stops startup. Stopping removes the cookie, and the next start rotates the token. Host and origin checks remain in place. `npm run test:reader:auth` exercises the real Reader utility and Chromium iframe with a temporary profile and a synthetic EPUB, including unauthorized requests, cross-origin rejection, cookie visibility and token rotation. This HTTP protection does not prevent a process with the same user's filesystem permissions from accessing library files directly.

The built Reader uses one owned Electron utility process: original compiled Fastify API on 127.0.0.1:5174 and a Vantilo static/proxy server on 127.0.0.1:5175. It does not reuse unrelated external services. Startup is on demand, concurrent starts coalesce, errors/port conflicts are surfaced, retry uses a new owned child, and shutdown is bounded. Fresh installs request each source’s newest issue; later checks preserve the source class’s incremental/idempotent behavior. Automatic checks happen when the reading service starts if due, and every three hours while that service/application remains running; closed apps do not update. Scheduler metadata is atomic and contains timestamps only. Partial/offline/rate-limited outcomes show a retry state; existing EPUBs are retained. “查看新刊” reloads the iframe only at the user’s request.

Network requests are limited to the existing fixed GitHub Contents repository and its corresponding raw-content path, reject redirects, do not inherit a developer GitHub token and bound response sizes/time. Tests use a synthetic EPUB and simulated GitHub responses, not public magazine downloads. Upstream availability, limits and publishing cadence determine what can be downloaded.

The API rejects mismatched Host, foreign Origin and cross/same-site Fetch-Site requests; frontend frame ancestors are limited to the local Vantilo origin and file-based Electron host. iframe sandbox disallows popup/top navigation, main validates frame navigation/redirects and rejects iframe IPC. These are web-boundary controls, not cryptographic authentication of another process running as the same OS user. There is no restored general browser/address bar or arbitrary navigation API.

## Youdao pronunciation-first with native matching-locale fallback — 2026-10-26

- At the user's request, word pronunciation now attempts the Youdao English-word recording `https://dict.youdao.com/dictvoice?audio=...&type=2` for **US** and `type=1` for **UK**, instead of always calling Web Speech first. The selected word is validated as a bounded, simple English word and encoded; no URL from dictionary/document content is trusted for playback. Dictionary lookup remains entirely on-device and AI contextual explanations are unchanged.
- Online `Audio.play()` is time-bounded to 1500 ms to prevent long waits on poor connectivity. ### Youdao pronunciation request and local persistence

- `scripts/reader-variant.mjs` replaces the original `frontend/App.tsx` playback function with `scripts/reader-pronunciation.ts`. The article word-click caller invokes it after dictionary lookup when `autoPronounceOnWordClick` is enabled; the manual word-detail US/UK buttons invoke it with fixed `"us"`/`"uk"` accents. Manual buttons are independent of the auto-pronunciation preference.
- The Vantilo adapter constructs a GET-style HTML audio URL at `https://dict.youdao.com/dictvoice?audio=<percent-encoded-English-word>&type=2` for US or `type=1` for UK, validates a bounded single English word, and calls `new Audio(url).play()`. No API key or user/article context is sent; the selected word and accent parameter are visible to the service. It does not validate the response MIME/content itself. Playback start is bounded to 1500 ms; rejected, stalled or timed-out playback is stopped and falls back to an exact-locale installed speech voice, with no US/UK cross-substitution. A new click cancels older pending audio/speech. Actual acoustic quality equivalence is not claimed.
- There is no Vantilo-managed audio download/cache or saved pronunciation recording in this playback path. The browser/Electron HTTP cache may be governed by response headers and is not app-controlled here. `pronunciationAccent` and `autoPronounceOnWordClick` are persisted with `magazine-reader-preferences-v1` in Reader localStorage; the default Vantilo build enables auto pronunciation and migrates the prior default once. They are included in the user-data backup and are removed when the user clears managed reading/learning data. The separate native dictionary cache at `userData/reader-library/data/vantilo-system-dictionary-cache-v3.json` stores text definitions, not audio, and is not removed by that localStorage clear. The clear operation does not explicitly purge Chromium's HTTP cache.
- Public-distribution authorization for this `dictvoice` endpoint remains unconfirmed in writing. The 0.1.11 release treats it as a disclosed third-party service risk and does not claim authorization. This note is not legal advice.
