# macOS 双架构测试包

Vantilo 当前准备 Apple Silicon（arm64）和 Intel（x64）两个测试包。两者界面和阅读器来自相同源码；Apple Silicon 使用 Swift MLX，Intel 使用 llama.cpp 与 GGUF 模型。模型权重不随应用打包。

Intel 当前允许选择已有的 Qwen3.5-4B Q4_K_M GGUF 文件并校验其大小与 SHA-256，尚未实现应用内下载。首次使用会加载模型。已在一台 2019 年 16GB Intel Mac 上对较早的 Intel 测试包进行过人工测试；新的候选包仍需在该设备上验收，不能以旧包的结果替代。

## 本机构建前提

`npm run build:mac:beta` 需要 Apple Silicon macOS、可用的本地 Magazine Reader 源码和依赖，以及预先准备的原生组件。它**不是**从公开仓库即可独立重现的发行流水线；构建脚本目前还存在本机路径和本机 Reader 依赖。源码、上游依赖的许可证、来源与版本必须在正式发布前核对。

构建时需要设置两个绝对路径：

- `VANTILO_BETA_ROOT`：`/private/tmp` 下尚不存在的候选包目录，脚本会拒绝覆盖。
- `VANTILO_BETA_INPUTS`：预先准备的依赖目录，含 Electron 45 双架构归档、Intel Codex 0.163.0、Intel 系统词典辅助程序及 `llama-x64/`。

`llama-x64/` 是官方 llama.cpp **b11904 Intel macOS** 运行组件的解压目录，包含 `llama-server`、依赖的动态库和 MIT 许可证。此次准备时所用的 `llama-b11904-bin-macos-x64.tar.gz` SHA-256 为 `6db49a9f390dda3af4fa4eabc4e12c74d9f3946be05c1aea555761f9b316e6a9`。构建脚本校验可执行文件架构，但调用者仍需事先核验归档、内容和许可证；不得从未知来源替换组件。

构建过程只允许从专用清单复制四种默认杂志的候选文件，不复制个人书库或模型权重。应用所有者已确认本人拥有或已取得四种杂志随应用分发和获取新刊的权利；这项确认未附书面材料，也未独立核验。候选清单必须记录准确的确认来源，不能把它描述为已核验书面授权。

## 验收与发布边界

- 两个候选包应来自同一份已审查源码，分别检查 CPU 架构、签名完整性、安装包校验值及干净安装和升级行为。
- Apple 芯片包应在 Apple Silicon 设备验证；Intel 包的原生运行时、已有模型选择、段落翻译、点词、取消和异常恢复必须在 Intel 设备实测。
- Reader 的会话认证、合成 EPUB 流程和隔离的助手通道需验证；真实账号或真实模型测试须单独说明，不能从模拟测试推断。
- 候选包使用 ad-hoc 签名，未经过 Developer ID 签名和 Apple 公证。测试者可能需要根据 macOS 提示确认打开。
- 软件更新当前只检查 GitHub 的稳定 Release 并打开发布页面，不自动安装；预发布版不触发稳定版更新提示。
- 检查源码和安装包中的第三方许可、隐私数据与构建内容，建立可回滚 Git 基线之后，才适合准备公开 Release。

不要把本地候选包描述为已经公开发布；不要将用户个人 EPUB、模型权重或登录资料加入源码提交。
